# ЖК «Береста»: лендинг. Спецификация

Дата: 2026-10-26 · Статус: утверждено Артёмом (прототип v3) · Бриф: [brief.md](../../../brief.md)

## 1. Цель и границы

Одностраничный лендинг, который продаёт квартиры в вымышленном ЖК «Береста» (Казань). Главное целевое действие: заявка на **персональный подбор** 3–5 квартир. Второе: **бронь онлайн** за 15 000 ₽ у каждой планировки.

**Источник правды для структуры, вёрстки и текстов:** [docs/prototype/prototype-v3.html](../../prototype/prototype-v3.html). Тексты в нём утверждены. Переносить дословно, менять только с согласия Артёма.

**В объёме:**
- Шапка, 10 секций прототипа (первый экран, район, двор, для кого, квартиры, сроки, как купить, застройщик, частые вопросы, форма подбора) и подвал.
- Окно брони, мобильная плашка с кнопками.
- 6 фотографий, сгенерированных через Codex, с одним и тем же домом на всех кадрах.
- 5 схем планировок в SVG.
- Публикация на GitHub Pages: `https://aislam23.github.io/beresta/`.

**Вне объёма (задел на следующие уроки, сейчас не делаем):**
- видео при скролле, 3D-генплан и выбор квартиры на схеме;
- страницы планировок, ход строительства, новости, ипотечный калькулятор;
- личный кабинет, CRM, шахматка, настоящая оплата;
- настоящая отправка заявок.

## 2. Визуальная система

Направление C «Береста» с широким туманным кадром из A.

Шрифт: **Manrope** (кириллица + латиница), веса 400–800, через встроенный Fonts API Astro с провайдером Fontsource. Заголовки 800, межбуквенный интервал −0.035…−0.05em.

### Правила
- **Контраст AA.** Белый на `#B9773F` даёт только 3,6:1, поэтому всё, где на меди лежит текст (кнопки «Забронировать» и «Получить подборку», карточка `6,6 млн ₽`, карточка «Бронь онлайн», цифра «0» у застройщика), делается на `--copper-strong` с белым текстом, включая подписи. Мелкий текст `.demo` в форме подбора (на тёмно-зелёном) получает цвет `#B5C3B1` (5,3:1), а не `#93A595`. В окне брони `.demo` остаётся `--ink-2`. Это единственное отличие от прототипа в цветах, Артём о нём предупреждён.
- **Никаких плашек над заголовками:** ни надзаголовков, ни тегов-пилюль, ни бейджей. Заголовок стоит сам по себе.
- Фирменный приём: «береста», то есть неровные тёмные чёрточки. Используется в логотипе и как разделитель между некоторыми секциями (`BarkDivider`). Больше нигде.
- Карточки: фон `--card`, рамка `--line`, радиус 16–20px. Акцентные карточки зелёные или медные, не больше одной-двух в ряду.
- Брейкпоинты: `980px` (планшет: 2 колонки, без навигации в шапке) и `640px` (телефон: 1 колонка, мобильная плашка внизу). Без горизонтального скролла на 360px.

### Тексты
- Перенос из прототипа дословно. Любой новый текст (alt, meta description, сообщения об ошибках) пишется по правилам эссе [ВП:Признаки сгенерированности текста](https://ru.wikipedia.org/wiki/Википедия:Признаки_сгенерированности_текста): без «от… до…», без «не X, а Y», без декоративных троек, без действий у предметов, без рекламных эпитетов («уникальный», «премиальный», «гармония»), без длинных тире, без фактов, которых нет в брифе.
- Неразрывные пробелы: между числом и единицей (`200 м`, `15 мин`, `6,6 млн ₽`), в диапазонах (`3–5 квартир` не переносится), после коротких предлогов в заголовках.

## 3. Архитектура

Astro 7 (статическая сборка), TypeScript strict, без UI-фреймворков. Стили: глобальные токены + `<style>` в компонентах. Клиентский JS только в двух местах: формы и окно брони. `<details>` для частых вопросов работает без JS.

**Принципы:**
- Цифры и факты живут только в `src/data/*`. Компоненты их не дублируют. Например, «200 м» из первого экрана и из блока «Район» берутся из одного места.
- Внутренние ссылки только якорные (`#area`, `#flats`, `#pick`). Ассеты идут через `import`/`<Image>`, поэтому `base` подставляется сам. Ссылки на `public/` делаются через `import.meta.env.BASE_URL`.
- Каждый компонент секции принимает данные через props или импортирует свой файл из `data/`. Компоненты секций не зависят друг от друга.

## 4. Формы и заявки

Две формы: **подбор** (`PickForm`: имя, телефон, бюджет, способ покупки, согласие) и **бронь** (`BookingDialog`: имя, телефон, согласие; тип квартиры подставляется из кнопки). В окно брони добавляется тот же чекбокс «Согласен на обработку персональных данных», которого не было в прототипе: без согласия собирать телефон нельзя. Варианты селектов «Бюджет» и «Как планируете покупать» лежат в `src/data/pickOptions.ts`.

У обеих форм стоит `novalidate`, а поля помечены `aria-required="true"` вместо `required`. Иначе браузер покажет свои подсказки и не даст увидеть наши ошибки.

```ts
// src/lib/leads.ts
export type LeadKind = 'pick' | 'booking';
export interface Lead {
  kind: LeadKind;
  name: string;
  phone: string;          // нормализованный: +7XXXXXXXXXX
  budget?: string;
  purchase?: string;
  flatType?: string;      // id из flats.ts, для брони
  consent: true;
}
export type LeadErrors = Partial<Record<'name' | 'phone' | 'consent', string>>;
export interface LeadInput { kind: LeadKind; name?: string; phone?: string; budget?: string; purchase?: string; flatType?: string; consent?: boolean }
export function validateLead(input: LeadInput): { ok: true; lead: Lead } | { ok: false; errors: LeadErrors };
export async function submitLead(lead: Lead): Promise<{ ok: true }>; // демо: задержка ~600 мс, console.info, ok
```

- `submitLead` сейчас никуда не шлёт данные. На уроке про CRM меняется только тело этой функции.
- Телефон принимает `+7…`, `7…`, `8…` и 10 цифр без кода, с пробелами, скобками и дефисами. После очистки должно остаться 10 цифр после кода страны, первая из них 9 (мобильный) или 3, 4, 8 (городской). Иначе ошибка «Проверьте номер телефона».
- Имя: 2–60 символов после обрезки пробелов, иначе «Напишите, как к вам обращаться».
- Согласие обязательно: «Нужно согласие на обработку данных».
- Ошибки показываются под полем (`aria-describedby`, `aria-invalid`), фокус уходит на первое поле с ошибкой. Кнопка на время отправки получает `disabled` и текст «Отправляем…».
- Успех: форма скрывается, показывается блок «Заявка принята» / «Бронь оформлена» с пометкой, что сайт учебный (тексты из прототипа). Фокус переводится на заголовок этого блока.
- Окно брони: нативный `<dialog>`, `showModal()`. Закрывается по Esc, по крестику и по клику на фон. После закрытия фокус возвращается на кнопку, которая его открыла. При каждом открытии состояние сбрасывается.

### Кадры

| id | Секция | Что в кадре | Пропорции |
|---|---|---|---|
| `01-hero` | Первый экран, **эталон** | Три корпуса над соснами со стороны реки, утренний туман, мягкий свет | 1536×1024 |
| `02-yard` | Двор | Двор без машин между корпусами, площадка, дети, сосны за домами | 1536×1024 |
| `03-family` | Для кого | Мама с коляской на тропинке в бору, дом виден за деревьями | 1536×1024 |
| `04-workfromhome` | Для кого | Рабочий стол у большого окна, за окном сосны и соседний корпус | 1536×1024 |
| `05-kitchen` | Для кого | Кухня-гостиная в светлом дереве, семья с подростками, окна на две стороны | 1536×1024 |
| `06-construction` | Для кого | Корпус 3 в строительстве, кран, корпуса 1–2 готовы, рассвет | 1536×1024 |

Codex генерирует только фиксированные размеры. Все кадры делаются горизонтальными 1536×1024 (3:2), без апскейла. Под слоты страницы (первый экран на всю ширину, карточки 4:3, мобильный первый экран высотой 420px) они кадрируются через CSS `object-fit: cover`, а точка кадрирования задаётся `object-position` у каждого кадра. Поэтому в промптах важное держим ближе к центру кадра. `<Picture>` получает `widths={[640, 960, 1280, 1536]}`.

`og.jpg` 1200×630 делается один раз скриптом `scripts/make-og.mjs` (sharp, `fit: cover`) из `01-hero.png` и коммитится в `public/og.jpg`. В `og:image` стоит абсолютный URL `https://aislam23.github.io/beresta/og.jpg`.

**Вёрстка не ждёт картинок.** Пока кадра нет, компонент `Photo` рисует градиентную заглушку из прототипа. Реестр кадров (`src/assets/photos/index.ts`) находит файлы через `import.meta.glob`, поэтому, когда png появляется, он сам подставляется вместо заглушки без правки кода. Генерация картинок идёт параллельно с вёрсткой.

### Как добиться одного и того же дома

1. **Библия дома** (`docs/images/building-bible.md`). Это неизменный английский блок, который вставляется в каждый промпт целиком:

   > Residential complex "Beresta" on the edge of a city, next to a pine forest and a river. Exactly THREE residential buildings forming a U-shaped quarter around a car-free courtyard. Building 1: 9 floors. Building 2: 12 floors. Building 3: 14 floors. Seen from the river they step up in height from left to right: 9, 12, 14. Flat roofs. Facades: warm off-white fibre-cement panels with vertical light larch wood lamellas between window columns; large windows in graphite-grey frames, regular grid, same window rhythm on every floor; the top floor of building 3 has setback penthouse terraces with glass railings. Ground floor of each building: tall 5-metre glazed lobby entrances with a thin copper-toned canopy. No balconies sticking out, no colourful accents, no logos or signage, no text. Mature tall pine trees in the foreground and around. Calm, realistic architectural photography, natural morning light, soft river fog, colour palette: warm white, graphite, dark pine green, muted copper. Photorealistic, 35mm lens, no people unless stated, no cars in the courtyard.

2. **Эталон первым.** `01-hero` генерируется без референса, пока Артём не выберет вариант (3–4 дубля). После выбора кадр становится эталоном, и до утверждения остальные кадры не делаются. **Это контрольная точка с Артёмом.**
3. **Все остальные кадры делаются с эталоном как референсом**: `codex exec -i src/assets/photos/01-hero.png`, а в промпте написано «use the attached image as the exact reference for the buildings: same number of buildings, same floor counts, same facade materials and window rhythm». Плюс полный текст библии и описание сцены.
4. **Проверка каждого кадра** (глазами, по чек-листу): видно 3 корпуса или их часть без лишних домов; этажность совпадает там, где её видно; фасад светлый с деревянными ламелями; рамки окон графитовые; во дворе нет машин; нет текста и логотипов; нет искажённых лиц и рук. Кадр, не прошедший проверку, перегенерируется (до 3 попыток), потом вопрос к Артёму.
5. Интерьеры (`04`, `05`) должны показывать за окном тот же фасад или сосны. Это проверяется так же.

### Скрипт

`scripts/gen-image.sh <id>`:
- берёт промпт кадра из `docs/images/shots.md` (секция `## <id>`) и библию;
- запускает `codex exec --skip-git-repo-check -s workspace-write -C <repo> [-i src/assets/photos/01-hero.png] "<промпт> Save the generated image to src/assets/photos/takes/<id>.take-N.png"`;
- если файла по указанному пути нет, берёт самый новый `png` из `~/.codex/generated_images/`, созданный после старта команды, и копирует его туда;
- дубль сохраняет как `src/assets/photos/takes/<id>.take-N.png` (папка в `.gitignore`).

`scripts/pick-take.sh <id> <N>` копирует выбранный дубль в `src/assets/photos/<id>.png`.

Картинки хранятся в репозитории в png и оптимизируются Astro при сборке (`<Image>` / `<Picture>` с `formats={['avif','webp']}`, `widths` под брейкпоинты). У каждого кадра осмысленный `alt` на русском по правилам текстов. Первый экран: `loading="eager"`, `fetchpriority="high"`. Остальные кадры лениво.

## 6. Схемы планировок

5 SVG-схем в `FloorPlan.astro` по `type`: `studio | one | two | three | penthouse`. Стиль линейный: стены `--ink` 3px, мокрые зоны `--pine-2`, подписи помещений с площадями без лишних деталей. Они должны соответствовать описаниям: кухня-ниша и французский балкон у студии, кухня-гостиная 16 м² у однокомнатной, мастер-спальня с гардеробной у двухкомнатной, две ванные и окна на две стороны у трёхкомнатной, терраса у пентхауса. Схемы условные, без размеров стен.

## 7. SEO, мета, доступность

- `<html lang="ru">`, `<title>ЖК «Береста» в Казани: квартиры у соснового бора</title>`, meta description по правилам текстов, OG-теги с `og.jpg`. `canonical` не ставим, потому что он противоречит `noindex`.
- **`<meta name="robots" content="noindex">`.** Проект вымышленный, телефон и адрес ненастоящие, поисковикам его показывать нельзя. Поэтому Lighthouse SEO в критерии приёмки не входит.
- JSON-LD `ApartmentComplex` с адресом и `numberOfAccommodationUnits` (490) для учебной полноты.
- Иконки двора (паркинг, площадка, лобби, кладовка) рисуются простыми inline-SVG по 24px с линией 1,75px вместо символов `P ◐ ⌂ ▤` из прототипа. У иконок `aria-hidden="true"`.
- Доступность: landmarks (`header`, `main`, `footer`, `nav`), один `h1`, `h2` у каждой секции, ссылка «Перейти к содержимому», видимый `:focus-visible`, у всех полей `label`, контраст не ниже AA (проверить медный текст на светлом фоне), `prefers-reduced-motion` отключает плавный скролл. Подписи у схемы района (`AreaMap`) дублируются списком расстояний рядом. Сама SVG-схема получает `role="img"` и `aria-label`.

## 8. Публикация

- `astro.config.mjs`: `site: 'https://aislam23.github.io'`, `base: '/beresta'`.
- `.github/workflows/deploy.yml` по официальной инструкции Astro: `actions/checkout@v7`, `withastro/action@v6`, `actions/deploy-pages@v5`, триггер push в `main` и `workflow_dispatch`. В репозитории закоммичен `package-lock.json`.
- Pages включаются с источником GitHub Actions: `gh api -X POST repos/aislam23/beresta/pages -f build_type=workflow`.
- Работа идёт в ветке `feat/landing`. CI-workflow `ci.yml` на pull request: `npm ci`, `npx playwright install --with-deps chromium`, `npm run check`, `npm run test`, `npm run test:e2e`. Branch protection не настраиваем: зелёный CI перед мержем считается договорённостью. Мерж в `main` запускает деплой.
